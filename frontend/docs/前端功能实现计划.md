# go-bald-admin-web 前端功能实现计划

## 1. 目标与边界

### 1.1 目标

基于现有 Vue 3 + TypeScript + Element Plus + Vite Admin 模板，接入 `go-bald-admin` 后端已完成的管理能力，形成可日常使用的前端：

1. 登录、退出、当前用户信息与权限路由；
2. 租户管理、用户管理；
3. 菜单、权限点、角色策略管理；
4. 字典类型与字典条目管理；
5. 文件上传、列表、下载、删除；
6. 操作与登录审计日志查询；
7. 完成构建、测试、代码风格检查和人工端到端验证。

### 1.2 不做范围

以下能力不在本轮前端实现中，避免范围蔓延：

- MFA、登录策略、组织架构、岗位、套餐配额；
- 内部消息、任务队列、SSE 推送、仪表盘统计；
- 多语言、API 资产管理、Redis 监控；
- 审计日志签名校验、密码策略管理；
- 通过菜单表自动生成 Vue Router 运行时路由。

> 菜单管理本轮只提供后台数据维护；页面路由仍使用前端静态路由 + 角色/权限过滤。待菜单与权限模型稳定后，再评估动态路由生成。

## 2. 现状与关键差异

### 2.1 前端现状

- 登录页仍指向模板接口：`auth/login`、`auth/captcha`；
- 当前用户接口仍指向模板接口：`users/me`；
- Axios 响应拦截器强制要求 `code/data/message` 包装；
- 业务页面主要是模板 Demo，尚未实现后端管理功能；
- Vite 代理仍指向 Apifox Mock；
- 动态路由权限过滤和 `v-permission` 指令已经可用。

### 2.2 后端协议差异

`go-bald-admin` Gin REST 接口返回裸 JSON，不返回模板的 `ApiResponseData<T>` 包装：

- 登录成功：`{ access_token, expires_at }`；
- 当前用户：`{ username, user_id, tenant_id, roles, token_type }`；
- 列表：`{ items/users, total, next_page_token? }`；
- 详情/创建/更新：嵌套对象，如 `{ tenant }`、`{ user }`；
- 删除：`{ deleted }`；
- 错误：常见为 `{ error }`，并配合 HTTP 状态码。

因此第一阶段必须先完成协议适配，不能直接在现有 API 封装上新增业务调用。

### 2.3 权限信息缺口

当前 `/v1/auth/whoami` 只返回 `roles`，不返回权限点列表。前端有两种可选方案：

1. **短期方案（推荐）**：页面访问使用角色过滤，按钮权限优先使用角色兜底，保证登录和管理主流程先可用；
2. **后续契约增强**：后端在 whoami 中补充 `permissions`，前端再启用完整按钮级权限码控制。

实施时保持 User Store 的 `permissions` 字段和权限判断逻辑不变，避免后续扩展时返工。

## 4. 接口映射

### 4.1 认证

| 功能     | 方法   | 路径              | 前端类型                                                  |
| -------- | ------ | ----------------- | --------------------------------------------------------- |
| 登录     | `POST` | `/v1/login`       | `{ username, password }` → `{ access_token, expires_at }` |
| 当前用户 | `GET`  | `/v1/auth/whoami` | `{ username, user_id, tenant_id, roles, token_type }`     |

登录页需要移除验证码逻辑和表单项；账号密码规则保留基本非空校验。

### 4.2 租户

| 功能 | 方法     | 路径              |
| ---- | -------- | ----------------- |
| 列表 | `GET`    | `/v1/tenant`      |
| 详情 | `GET`    | `/v1/tenant/{id}` |
| 创建 | `POST`   | `/v1/tenant`      |
| 更新 | `PUT`    | `/v1/tenant/{id}` |
| 删除 | `DELETE` | `/v1/tenant/{id}` |

### 4.3 用户

| 功能             | 方法     | 路径            |
| ---------------- | -------- | --------------- |
| 当前租户用户列表 | `GET`    | `/v1/user`      |
| 详情             | `GET`    | `/v1/user/{id}` |
| 创建             | `POST`   | `/v1/user`      |
| 更新             | `PUT`    | `/v1/user/{id}` |
| 删除             | `DELETE` | `/v1/user/{id}` |

用户列表按当前 JWT 租户自动隔离，前端不传 `tenant_id`。

### 4.4 菜单、权限点与角色策略

| 功能         | 方法                  | 路径                                    |
| ------------ | --------------------- | --------------------------------------- |
| 菜单树       | `GET`                 | `/v1/menu`                              |
| 菜单 CRUD    | `GET/POST/PUT/DELETE` | `/v1/menu`, `/v1/menu/{id}`             |
| 权限点列表   | `GET`                 | `/v1/permission`                        |
| 权限点 CRUD  | `GET/POST/PUT/DELETE` | `/v1/permission`, `/v1/permission/{id}` |
| 角色策略列表 | `GET`                 | `/v1/permission/policy`                 |
| 新增角色策略 | `POST`                | `/v1/permission/policy`                 |
| 删除角色策略 | `DELETE`              | `/v1/permission/policy/{id}`            |

### 4.5 字典

| 功能          | 方法                  | 路径                                    |
| ------------- | --------------------- | --------------------------------------- |
| 字典类型列表  | `GET`                 | `/v1/dict_type`                         |
| 字典类型 CRUD | `GET/POST/PUT/DELETE` | `/v1/dict_type`, `/v1/dict_type/{id}`   |
| 指定类型条目  | `GET`                 | `/v1/dict_entry?type_code={type_code}`  |
| 全量条目      | `GET`                 | `/v1/dict_entry`                        |
| 字典条目 CRUD | `GET/POST/PUT/DELETE` | `/v1/dict_entry`, `/v1/dict_entry/{id}` |

### 4.6 文件

| 功能       | 方法     | 路径                      | 说明                                                 |
| ---------- | -------- | ------------------------- | ---------------------------------------------------- |
| 上传       | `POST`   | `/v1/files/upload`        | Gin 支持 `multipart/form-data`：`file` + `directory` |
| 下载       | `GET`    | `/v1/files/{id}/download` | 前端使用 `responseType: "blob"`                      |
| 元数据列表 | `GET`    | `/v1/files`               | 支持 `file_name`、`mime_type` 过滤                   |
| 详情       | `GET`    | `/v1/files/{id}`          |                                                      |
| 删除       | `DELETE` | `/v1/files/{id}`          |                                                      |

### 4.7 审计

| 功能     | 方法  | 路径             |
| -------- | ----- | ---------------- |
| 分页查询 | `GET` | `/v1/audit`      |
| 详情     | `GET` | `/v1/audit/{id}` |

查询条件：`category`、`subject`、`object`、`action`、`result`、`ip`、`page_size`、`page_token`。

## 5. 实施里程碑

### F0：协议、代理与登录（最高优先级）

**目标**：替换模板认证链路，前端可以登录真实后端并进入受角色保护的管理路由。

**任务**

1. 新增 `.env.development` / `.env.production`：
   - `VITE_BASE_URL=/api`；
   - 生产环境由部署层反向代理 `/api` 到后端。
2. 调整 `vite.config.ts`：
   - 代理 `/api` → `http://127.0.0.1:8080`；
   - rewrite 去掉 `/api` 前缀；
   - 移除 Apifox Mock。
3. 调整 Axios：
   - 成功响应直接返回后端裸 JSON；
   - `blob/arraybuffer` 保持直通；
   - HTTP 错误优先读取 `response.data.error`；
   - 401 触发登出并跳转登录页；
   - 上传接口允许更长超时。
4. 新增 `src/common/apis/auth/`：
   - `loginApi(data)`；
   - `getCurrentUserApi()`。
5. 登录页：
   - 移除验证码 API、校验和视觉遮罩；
   - 提交 `{ username, password }`；
   - 保存 `access_token`；
   - 登录成功后按 redirect 或默认路径跳转。
6. User Store：
   - whoami 映射 `username/user_id/tenant_id/roles`；
   - `permissions` 暂置空数组，保留后续扩展；
   - 清理模板切换用户逻辑。
7. 路由：
   - 移除或隐藏模板 Demo 权限页；
   - 新增业务路由骨架；
   - 管理页面 `meta.roles: ["admin"]`，只读页面可扩展 `viewer`。

**验收**

- `admin/admin123` 登录成功并进入首页；
- 错误密码提示“未授权”或后端错误信息；
- Token 过期或手工清除后端会话时跳转登录页；
- viewer 不显示仅 admin 可见的页面入口，直接访问被路由守卫拦截；
- `pnpm build` 通过。

### F1：通用管理页基础能力

**目标**：建立统一的 CRUD 交互和列表能力，降低后续页面重复代码。

**任务**

1. 类型规范：
   - Timestamp 统一为 string，展示时格式化；
   - 列表响应使用 `{ items, total }`；
   - 审计使用 `{ items, total, next_page_token }`。
2. 新增 `usePagedList`：
   - 支持全量小列表本地分页；
   - 支持审计的 `page_token` 服务端分页；
   - 统一 loading、刷新、页码变化。
3. 新增 `useConfirmAction`：
   - 删除前 `ElMessageBox.confirm`；
   - 请求失败不额外重复弹错（由 Axios 统一提示）；
   - 成功后刷新当前列表。
4. 建立统一表格风格：
   - 使用 Element Plus Table；
   - 操作列固定右侧；
   - 空态、加载态、行操作权限控制；
   - 日期、枚举、状态使用可复用展示组件。
5. 新增页面骨架和路由：
   - 租户、用户、系统、字典、文件、审计；
   - 菜单标题、图标、顺序一次性定义。

**验收**

- 所有业务路由可访问且侧边栏层级清晰；
- 通用分页和确认逻辑有单元测试；
- 空态、加载态、错误态不出现布局抖动。

### F2：租户与用户管理

**目标**：完成身份基础数据管理。

**任务**

1. 租户页：
   - 列表：ID、名称、状态、备注、创建/更新时间；
   - 创建：ID、名称、备注；
   - 编辑：名称、状态、备注；
   - 删除：二次确认，提示影响范围；
   - 状态使用 Tag 展示：启用 / 禁用 / 冻结。
2. 用户页：
   - 列表：ID、用户名、角色、创建/更新时间；
   - 创建：ID、用户名、角色、初始密码；
   - 编辑：用户名、角色、可选重置密码；
   - 删除：二次确认；
   - 当前租户信息从 User Store 展示，但不允许前端手工切换租户。
3. 权限：
   - 页面入口按 admin 控制；
   - 写操作按钮使用 `v-permission` 绑定角色或后续权限码。

**验收**

- 租户 CRUD 全链路可用；
- 用户 CRUD 全链路可用；
- viewer 执行写操作时后端返回 403，前端提示明确；
- 用户列表只显示当前租户数据；
- 删除后列表和总数正确刷新。

### F3：菜单、权限点与角色策略

**目标**：完成权限数据维护入口。

**任务**

1. 菜单页：
   - 以树形表格展示 `ListMenus` 根节点数组；
   - 创建/编辑字段：父节点、类型、名称、路径、组件、标题、图标、顺序、状态、备注；
   - 删除前明确提示“递归删除子树”；
   - BUTTON 类型隐藏组件字段，路径输入提示填写动作名。
2. 权限点页：
   - 列表：ID、名称、关联菜单、备注、时间；
   - 创建/编辑权限点元数据；
   - 删除提示“仅删除元数据，不联动角色策略”。
3. 角色策略页：
   - 列表：ID、角色、资源对象、动作；
   - 创建：角色、对象、动作；
   - 删除按策略 ID；
   - 页面显著提示“策略变更需后端重启后生效”。
4. 权限页签：
   - 使用 Tabs 区分“权限点”和“角色策略”，或拆分为两个子路由。

**验收**

- 菜单树父子层级和展开状态正确；
- 权限点 CRUD 可用；
- 角色策略创建、删除、列表可用；
- 重复策略、必填字段缺失等后端错误能正常展示；
- admin 可访问，viewer 被拒绝。

### F4：字典管理

**目标**：完成字典类型与条目维护。

**任务**

1. 字典类型页：
   - 列表：类型编码、名称、状态、备注、时间；
   - 创建后类型编码不可编辑；
   - 删除提示“级联删除全部条目并失效缓存”。
2. 字典条目页：
   - 顶部选择字典类型，加载 `/v1/dict_entry?type_code=...`；
   - 列表：业务键、值、标签、数值、排序、状态、备注；
   - 创建：类型、值、标签、数值、排序、备注；
   - 编辑时 `type_code/value` 只读；
   - 启用状态和数值支持“清空/改回空值”语义，通过 `*_set` 字段提交。
3. 交互细节：
   - 类型切换时重置分页；
   - 保存成功后刷新条目；
   - 删除后刷新当前类型。

**验收**

- 类型 CRUD 可用；
- 指定类型条目 CRUD 可用；
- 条目按 `sort_order` 升序展示；
- `type_code:value` 唯一冲突提示正常；
- viewer 只读，写操作返回 403 时提示正常。

### F5：文件管理

**目标**：完成文件上传、检索、下载和删除。

**任务**

1. 上传：
   - 使用 `FormData`，字段 `file` 与 `directory`；
   - 请求头设置为 `multipart/form-data`；
   - 上传进度、取消或禁用重复提交；
   - 前端预校验 50MiB 大小，后端仍作为最终校验。
2. 列表：
   - 元数据：文件名、目录、扩展名、大小、MIME、SHA256、上传者、时间；
   - 过滤：原始文件名前缀、MIME 类型；
   - 大小格式化，SHA256 支持复制。
3. 下载：
   - `responseType: "blob"`；
   - 使用后端 `Content-Disposition` 中的文件名，缺失时使用元数据 `file_name`；
   - 触发浏览器保存。
4. 删除：
   - 二次确认；
   - 成功后刷新列表。

**验收**

- 上传、列表、下载、删除全链路可用；
- 下载内容与上传内容一致；
- 超过 50MiB 或 MIME 不允许时错误提示明确；
- 上传过程中按钮状态正确，重复提交被阻止。

### F6：审计日志

**目标**：提供操作与登录审计查询能力。

**任务**

2. 列表：
   - 时间、租户、分类、主体、对象、动作、结果、IP、UA、Request ID、Trace ID；
   - 长字段省略并提供详情抽屉；
   - 结果使用 Tag：allow / deny / error。
3. 服务端分页：
   - 使用 `page_size` 与 `next_page_token`；
   - “下一页 / 上一页”基于已保存 token 栈；
   - 最后一页禁用下一页。
4. 详情：
   - 展示完整记录与错误信息；
   - Request ID / Trace ID 支持复制。

**验收**

- 可分别查询操作日志和登录日志；
- 过滤条件正确传参；
- page token 翻页不重复、不跳页；
- 403 权限错误提示正常；
- 长文本不影响表格布局。

| F4   | 字典类型与条目             |     1 天 | F1                 |
| F5   | 文件管理                   |     1 天 | F1，MinIO 可用     |

总计约 7.5–9 个工作日。若后端 whoami 补充 `permissions`、角色策略支持热加载，可在对应阶段启用更完整的按钮级权限和实时策略体验。

## 8. 风险与应对

| 风险                     | 影响               | 应对                                      |
| ------------------------ | ------------------ | ----------------------------------------- |
| Axios 强依赖模板包装响应 | 所有新接口不可用   | F0 先改协议适配，测试通过后再开发页面     |
| whoami 无 permissions    | 按钮级权限码不可用 | 短期使用 roles；保留 permissions 数据结构 |
| 角色策略修改需重启       | 用户误解已即时生效 | 页面显著提示生效时机                      |
| 文件上传受网络影响       | 5 秒默认超时不足   | 单独设置较长 timeout 和进度反馈           |
| 审计 page token 分页     | 不能按页码跳转     | 保存 token 栈，仅提供上一页/下一页        |
| 模板 Demo 与业务路由混杂 | 交付体验差         | F7 统一隐藏或删除模板入口                 |
